# Seguridad y privacidad

No publiques secretos, contratos o datos de personas en issues o PR. Para una incidencia sensible utiliza el canal privado que habilite el mantenedor; si no está disponible, contacta por un canal corporativo verificado sin adjuntar datos y solicita uno seguro. No inventamos una dirección de seguridad ni afirmamos que Private Vulnerability Reporting esté activo.

Sitio estático: sin autenticación, subida de ficheros, ejecución de órdenes, SDK externos, analítica o backend. Los enlaces externos solo se abren al elegirlos. Mantener CSP restrictiva y dependencias mínimas. Trabajar con casos ficticios; probar controles solo en entornos propios autorizados. No realizar exploración, explotación ni recolección de datos de terceros desde este proyecto.

El escaneo editorial de patrones no prueba ausencia de secretos. Si se encuentra uno, limitar difusión, revocar/rotar y tramitar saneamiento de historial mediante procedimiento acordado; borrarlo del último commit no lo elimina de Git.
